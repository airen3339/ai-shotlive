## 简介

导出状态管理模块是AI视频生成工作流中的关键组件，负责监控和展示从剧本创作到最终视频导出的完整流程状态。该模块实现了复杂的进度计算算法、实时状态面板显示逻辑、估算时长计算以及完成镜头统计等功能。

本模块的核心目标是为用户提供清晰、准确的进度反馈，包括当前完成百分比、剩余时间预测、当前阶段标识等信息。通过状态监听机制和UI更新策略，确保用户能够实时了解导出进程的进展情况。

### 进度计算算法

进度计算算法是导出状态管理的核心，实现了多维度的进度评估机制：

#### 资产准备阶段进度计算

```mermaid
flowchart TD
Start(["开始计算"]) --> CheckCharacters["检查角色数量"]
CheckCharacters --> CharactersExist{"角色存在？"}
CharactersExist --> |否| SetZero["设置进度为0%"]
CharactersExist --> |是| CountRefImages["统计有参考图的角色数"]
CountRefImages --> CalculatePercentage["计算完成百分比"]
CalculatePercentage --> RoundPercentage["四舍五入到整数"]
RoundPercentage --> CheckCompletion{"是否完成？"}
CheckCompletion --> |是| SetComplete["标记为完成"]
CheckCompletion --> |否| SetActive["标记为进行中"]
SetZero --> End(["结束"])
SetComplete --> End
SetActive --> End
```

#### 导演阶段进度计算

导演阶段的进度计算基于镜头生成的完成情况：

- **分子**：已完成视频生成的镜头数量
- **分母**：总镜头数量
- **计算公式**：进度百分比 = (已完成镜头数 / 总镜头数) × 100%

#### 全局进度聚合

全局进度通过加权平均的方式计算：

```
全局进度 = Σ(阶段权重 × 阶段进度) / Σ(阶段权重)
```

其中各阶段的权重分配如下：
- 资产准备：30%
- 导演阶段：40%
- 渲染导出：30%

#### 状态徽章系统

状态徽章根据当前状态显示不同的视觉标识：

|------|------|------|------|

#### 时间预测算法

剩余时间的预测基于指数移动平均算法：

```
预测剩余时间 = 当前时间 × α + 历史平均时间 × (1 - α)
```

其中α为平滑因子，取值范围(0,1)，用于平衡实时性和稳定性。

### 完成镜头统计

#### 统计指标计算

- **总镜头数**：项目中镜头的总数
- **已完成镜头数**：状态为"已完成"的镜头数量
- **完成率**：已完成镜头数 / 总镜头数 × 100%
- **平均生成时间**：所有已完成镜头的平均生成时间
- **成功率**：成功生成的镜头数 / 总生成尝试数 × 100%

### 错误状态处理

#### 错误分类体系

系统将错误分为以下几类：

| 错误类型 | 描述 | 处理策略 |
|----------|------|----------|
| 临时性错误 | 网络中断、API超时 | 自动重试 |
| 持久性错误 | 参数错误、权限不足 | 手动修复 |
| 资源错误 | 存储空间不足、内存溢出 | 系统级处理 |
| 业务错误 | 数据验证失败、业务规则违反 | 用户干预 |

#### 错误恢复机制

```mermaid
flowchart TD
ErrorDetected["检测到错误"] --> ClassifyError["分类错误类型"]
ClassifyError --> TemporaryError{"临时性错误？"}
TemporaryError --> |是| AutoRetry["自动重试"]
TemporaryError --> |否| ManualFix["手动修复"]
AutoRetry --> RetryCount{"重试次数<限制？"}
RetryCount --> |是| RetryOperation["重试操作"]
RetryCount --> |否| PromoteToManual["升级为手动修复"]
RetryOperation --> Success{"操作成功？"}
Success --> |是| ResumeProcess["恢复正常流程"]
Success --> |否| PromoteToManual
ManualFix --> UserIntervention["用户干预"]
PromoteToManual --> UserIntervention
ResumeProcess --> UpdateStatus["更新状态"]
UserIntervention --> UpdateStatus
UpdateStatus --> End(["结束"])
```

## 性能考虑

### 内存优化策略

#### 状态管理优化

系统采用了高效的内存管理模式：

- **状态分片**：将大型状态对象分割为多个小对象，减少不必要的重渲染
- **引用缓存**：对计算结果进行缓存，避免重复计算
- **垃圾回收**：及时清理不再使用的临时数据

#### 组件渲染优化

```mermaid
flowchart TD
RenderRequest["渲染请求"] --> CheckState["检查状态变化"]
CheckState --> StateChanged{"状态发生变化？"}
StateChanged --> |否| SkipRender["跳过渲染"]
StateChanged --> |是| ComputeDiff["计算差异"]
ComputeDiff --> ApplyChanges["应用变更"]
ApplyChanges --> UpdateDOM["更新DOM"]
SkipRender --> End(["结束"])
UpdateDOM --> End
```

### 网络性能优化

#### 请求合并

系统实现了智能的请求合并机制：

- **批量请求**：将多个小请求合并为批量请求
- **请求去重**：避免重复发送相同的请求
- **缓存策略**：合理利用缓存减少网络请求

#### 异步处理

```mermaid
sequenceDiagram
participant UI as "用户界面"
participant Queue as "任务队列"
participant Worker as "工作线程"
participant API as "API服务"
UI->>Queue : 添加任务

UI-->>UI : 触发重新渲染
```

### 计算性能优化

#### 并行计算

系统支持多任务并行处理：

- **CPU密集型任务**：使用Web Workers避免阻塞主线程
- **I/O密集型任务**：使用异步操作提高效率
- **缓存策略**：对昂贵的计算结果进行缓存

#### 算法优化

进度计算采用了优化的算法：

- **增量计算**：只计算变化的部分，而不是重新计算全部
- **近似算法**：在保证精度的前提下使用更快的算法
- **预计算**：提前计算可能需要的数据

## 故障排除指南

### 常见问题诊断

#### 进度停滞问题

**症状**：进度条长时间不变化

**诊断步骤**：
1. 检查网络连接状态
2. 查看是否有正在进行的任务
3. 验证AI服务的可用性
4. 检查存储空间是否充足

**解决方案**：
- 重新建立网络连接
- 取消并重新启动卡住的任务
- 检查并修复AI服务配置
- 清理存储空间

#### 状态显示异常

**症状**：状态徽章显示不正确

**诊断步骤**：
1. 检查状态计算逻辑
2. 验证状态转换规则
3. 确认UI组件的渲染逻辑

**解决方案**：
- 修复状态计算算法
- 更新状态转换条件
- 修正UI渲染逻辑

#### 时间预测不准确

**症状**：剩余时间预测与实际不符

**诊断步骤**：
1. 检查历史数据的准确性
2. 验证预测算法的参数
3. 确认当前负载情况

**解决方案**：
- 更新历史统计数据
- 调整预测算法参数
- 考虑当前系统负载影响
