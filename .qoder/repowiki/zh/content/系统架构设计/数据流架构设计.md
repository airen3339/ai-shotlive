## 简介
本文件系统性梳理 AI Shotlive 的数据流架构，覆盖从前端状态变更到后端持久化的完整链路，重点阐释以下方面：
- 增量 PATCH 保存机制与冲突处理
- 实时渲染日志处理与前端展示
- 异步任务的状态同步与重试策略
- 项目锁机制、并发控制与数据一致性保障
- 用户数据隔离、缓存策略与数据迁移方案
- 数据验证规则、错误恢复机制与性能监控指标

## 项目结构
项目采用前后端分离架构，前端基于 React/Vite 构建，后端基于 Node.js + Express，数据库配置支持 SQLite/MySQL。核心模块包括：
- 前端服务层：AI 适配器、存储服务、任务服务、渲染日志服务等
- 后端路由层：项目管理、增量补丁、任务调度、数据传输等
- 中间件与配置：认证中间件、数据库连接配置
- 业务服务：任务执行器、项目存储、文件存储、脚本解析等

## 详细组件分析

### 增量 PATCH 保存机制
- 设计目标：最小化网络传输与数据库写入，提升响应速度与降低冲突概率
- 关键流程：
  - 前端收集自上次提交以来的变更集合
  - 将变更序列化为 PATCH 请求发送至后端
  - 后端路由接收 PATCH 并调用项目存储服务进行合并
  - 存储服务应用变更并返回合并后的最新版本
- 冲突处理：
  - 版本号校验：若客户端版本号与服务器不一致，拒绝合并并要求重试
  - 分支合并：对同一字段的并发修改采用最后写入获胜或时间戳优先策略
  - 回滚机制：合并失败时回滚到上一个稳定版本

```mermaid
flowchart TD
Start(["开始 PATCH 流程"]) --> Collect["收集本地变更"]
Collect --> Serialize["序列化为 PATCH 包"]
Serialize --> Send["发送至后端路由"]
Send --> Apply["项目存储服务合并"]
Apply --> MergeOK{"合并成功?"}
MergeOK --> |是| Persist["持久化到数据库"]
MergeOK --> |否| Conflict{"检测到冲突?"}
Conflict --> |是| Rebase["重放/回滚并重试"]
Conflict --> |否| Rollback["回滚到稳定版本"]
Persist --> Notify["通知前端更新状态"]
Rebase --> Send
Rollback --> Notify
Notify --> End(["结束"])
```

### 异步任务状态同步
- 任务生命周期：创建 -> 提交 -> 轮询 -> 完成/失败
- 状态模型：待处理、执行中、完成、失败、取消
- 同步策略：
  - 前端定时轮询或订阅 WebSocket 获取最新状态
  - 后端任务执行器定期更新数据库状态
  - 幂等性：重复状态更新不会破坏最终一致性
- 重试与超时：指数退避重试、超时阈值与告警联动

### 项目锁机制与并发控制
- 项目级互斥：同一项目同时仅允许一个写操作，避免竞态条件
- 锁实现：
  - 前端：在 PATCH 提交期间禁用相关按钮，显示加载状态
  - 后端：基于内存/Redis 的分布式锁，或数据库行级锁
- 并发策略：
  - 读多写少场景：共享读锁，独占写锁
  - 高冲突场景：乐观锁（版本号）+ 悲观回退
- 数据一致性：
  - 事务包裹关键写入操作
  - 两阶段提交（可选）用于跨表/跨库一致性

```mermaid
flowchart TD
A["请求进入"] --> B{"是否持有项目写锁?"}
B --> |否| C["尝试获取写锁"]
C --> D{"获取成功?"}
D --> |是| E["执行写操作"]
D --> |否| F["等待/重试"]
B --> |是| G["拒绝请求/排队"]
E --> H["释放锁"]
F --> A
G --> A
```

### 用户数据隔离与缓存策略
- 数据隔离：
  - 认证中间件确保每个请求绑定用户上下文
  - 所有读写操作均附加用户标识，防止越权访问
- 缓存层次：
  - 前端：IndexedDB 本地缓存 + Redux/Zustand 状态缓存
  - 后端：Redis 缓存热点数据（如项目元数据）
  - 文件缓存：生成资源的 CDN/对象存储缓存
- 缓存失效：
  - 写操作触发缓存失效
  - 定期清理过期缓存与临时文件

## 故障排除指南
- 常见问题：
  - PATCH 冲突：检查版本号与重试策略
  - 任务卡死：查看后端日志与重试队列
  - 渲染日志缺失：确认 SSE 连接与去重逻辑
  - 权限错误：核对认证中间件与用户上下文
- 排查步骤：
  - 查看后端错误日志与审计记录
  - 使用任务 ID/项目 ID 快速定位
  - 本地复现：关闭缓存/禁用代理
- 回滚与修复：
  - 自动回滚脚本
  - 手动修复工具与数据对账

## 结论
本架构以“增量 PATCH + 任务驱动 + 严格锁与中间件”为核心，结合前后端缓存与迁移脚本，实现了高效、可靠且可扩展的数据流体系。建议在生产环境中进一步完善：
- 项目锁的分布式实现与监控
- 更细粒度的缓存失效策略
- 任务超时与熔断机制
- 数据一致性审计与合规追踪
